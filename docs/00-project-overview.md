# 00 - نظرة عامة على المشروع

## 1. اسم المشروع

نظام إدارة بقالة أونلاين متعدد العمال (Grocery Store Management System).

## 2. الهدف العام من النظام

بناء نظام إداري متكامل لبقالة صغيرة أو متوسطة، يتيح لصاحب البقالة (المالك) ومدرائه وعماله إدارة:

- العملاء وديونهم وسدادهم.
- التجار والموردين والمشتريات (آجلة ونقدية).
- المصاريف والخرج اليومي.
- البيع بثلاث طرق: تفصيلي، سريع بمبلغ، أو دخل يومي إجمالي.
- المخزون بشكل اختياري قابل للتفعيل أو الإيقاف.
- التقارير المالية والإدارية (دقيقة أو تقديرية حسب وضع البيع).
- الإشعارات الداخلية وزر واتساب برسائل جاهزة.
- سجل الحركات (Audit Log) لكل عملية مهمة.

النظام يهدف إلى:

1. **التحكم المالي الدقيق**: لا حذف نهائي للعمليات المالية، كل تعديل أو إلغاء موثّق.
2. **مرونة الصلاحيات**: الأدمن يستطيع إنشاء أدوار وتعديل صلاحياتها بنفسه (RBAC ديناميكي).
3. **سهولة الاستخدام داخل البقالة**: واجهة عربية، Mobile-first، PWA، مناسبة للعامل أثناء العمل.
4. **حماية ضد التلاعب**: كل العمليات تمر عبر الباكند، الأرصدة لا تعدّل من الواجهة، Audit Logs على كل شيء.

## 3. طبيعة النظام

| البند | القيمة |
|---|---|
| نوع المشروع | نظام إدارة متكامل لبقالة |
| عدد المتاجر في v1 | بقالة واحدة (مع `store_id` لدعم متعدد لاحقاً) |
| طريقة التشغيل | أونلاين فقط عبر PWA |
| اللغة | العربية فقط |
| العملة | تُختار من الإعدادات (مثل ريال يمني) |
| النشر | Railway (Frontend + Backend + PostgreSQL) |

## 4. المستخدمون

- **المالك (Owner)**: يمتلك كل الصلاحيات.
- **المدير (Manager)**: معظم الصلاحيات الإدارية والتقارير.
- **عامل المبيعات (Sales Worker)**: عمليات البيع وديون العملاء فقط.
- **المحاسب (Accountant)**: العرض والتقارير المالية بدون تعديل.
- **مسؤول مشتريات (Purchasing Officer)**: إدارة التجار والمشتريات.
- **مسؤول مخزون (Inventory Officer)**: إدارة المنتجات وحركات المخزون.

> الأدوار مرنة، والأدمن يستطيع إنشاء أي دور جديد وتخصيص صلاحياته.

## 5. منصة التشغيل

- **Frontend**: React + TypeScript + Vite + Ionic React + Tailwind CSS كتطبيق PWA.
- **Backend**: NestJS + TypeScript REST API.
- **Database**: Railway PostgreSQL (ليس Supabase ولا Neon ولا أي خدمة خارجية).
- **ORM**: Prisma.
- **Architecture**: Monorepo.
- **Deployment**: Railway للفرونت اند والباك اند وقاعدة البيانات.

## 6. مخطط البنية العامة

```text
   جوال العامل / المدير
            │
            ▼
   Frontend PWA (Railway)
            │  HTTPS / REST + JWT
            ▼
   NestJS API (Railway)
            │  Prisma
            ▼
   Railway PostgreSQL
```

## 7. ميزات أساسية مميزة

1. **RBAC Dynamic**: صلاحيات مرنة، الأدمن يصنع أدواره.
2. **3 أوضاع للبيع**: تفصيلي / سريع بمبلغ / دخل يومي إجمالي + وضع هجين.
3. **مخزون اختياري**: على مستوى النظام والمنتج.
4. **3 أوضاع لحساب الربح**: دقيق / تقديري / يدوي.
5. **Audit Log**: يسجل كل شيء مهم.
6. **No Hard Delete**: حذف ناعم وإلغاء فقط للعمليات المالية.
7. **Database Transactions**: كل عملية مالية داخل Prisma transaction.
8. **3 مستويات صلاحيات للتقارير**: عرض، طباعة، تصدير.
9. **زر واتساب برسالة جاهزة** (بدون API تلقائي في v1).
10. **تحليل سلوك العملاء** (بعد توفر بيانات كافية).
