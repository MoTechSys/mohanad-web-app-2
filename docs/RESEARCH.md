# دراسة متطلبات نظام البقالة — «دفتر البقالة»

> دراسة تحليلية مكثّفة لمتطلبات نظام إدارة ونقطة بيع لبقالة صغيرة/متوسطة، تعمل بلا إنترنت على هاتف أندرويد واحد، مع تحقق محاسبي كامل.
> التطوير: **معين العباسي** — [alabbasi.uk](https://alabbasi.uk) — +967 770 941 666

---

## 1. نطاق الدراسة

| البند | القرار |
|---|---|
| نوع المنشأة | بقالة (ليس سوبرماركت ولا سلسلة) — مالك/كاشير واحد |
| الاتصال | **بلا إنترنت نهائيًا** — كل البيانات على الجهاز (Hive) |
| الجهاز | هاتف أندرويد (arm64 / arm32) — الكاميرا هي الماسح |
| العملة | ريال يمني افتراضيًا (قابل للتغيير) — أعداد صحيحة بالقروش |
| المستخدمون | مستخدم واحد + قفل PIN |

## 2. مصادر الدراسة (ملخّص)

جُمعت المتطلبات من مقارنة أنظمة POS شائعة للبقالات (Clover, NRS, Nexchar, Zynta, BMC POS، وغيرها) ومن الممارسات المحاسبية للمنشآت الصغيرة. أبرز الخلاصات التي تُجمِع عليها المصادر:

1. **سرعة المسح دون ثانية** هي المعيار الأول: الكاشير يمسح ويظهر الصنف فورًا مع صوت تأكيد، والمسح المتكرر لنفس الصنف يزيد الكمية تلقائيًا.
2. **البحث البديل**: كثير من أصناف البقالة (خبز، خضار، أصناف بالوزن) بلا باركود → لازم بحث سريع بالاسم + أزرار «أصناف سريعة».
3. **صنف غير معروف = فرصة إدخال**: عند مسح باركود غير مسجّل يجب أن يُتاح إنشاء الصنف فورًا (اسم + سعر) دون مغادرة شاشة البيع.
4. **الآجل (الدَّين) جوهري في البقالات العربية**: بيع آجل لعميل مسجّل مع حد ائتمان وتجميد.
5. **المخزون تقريبي لكن مفيد**: تنبيه نقص المخزون، تقييم بسعر الشراء، استلام بضاعة بالمسح.
6. **التقارير اليومية** (نقدية اليوم، مبيعات، مصاريف، صافي) هي الأكثر استخدامًا.
7. **الثيم الداكن** مطلوب للعمل الليلي وتقليل استهلاك البطارية على شاشات OLED.
8. **النسخ الاحتياطي** المحلي ضروري لأن البيانات على جهاز واحد.

## 3. تدفق الكاشير المستهدف («طق طق طق»)

```
فتح الكاشير ──► الكاميرا تعمل فورًا
   │
   ├─ مسح باركود معروف ──► صوت «بيب» + الصنف يُضاف/الكمية +1 + السلة تتحدث
   ├─ مسح باركود غير معروف ──► صوت تحذير + ورقة «صنف جديد» (الاسم/السعر) ──► يُضاف للسلة
   ├─ كتابة اسم/باركود يدويًا ──► نتائج فورية ──► لمسة تضيف
   ├─ لمس «أصناف سريعة» (بلا باركود) ──► يُضاف
   │
   ├─ تعديل كمية/سعر/حذف سطر  ─ خصم على الفاتورة
   │
   └─ إتمام: نقدي (مع حساب الباقي) | آجل (اختيار عميل + التحقق من الحد)
         └─► فاتورة + حركة مخزون + قيد دين (ذرّي) ──► سلة جديدة
```

### مواصفات دقيقة
- زمن من المسح إلى ظهور الصنف: < 300ms (بحث في خريطة `barcode → product` بذاكرة O(1)).
- منع التكرار الشبحي: تجاهل نفس الباركود خلال 1200ms (debounce).
- ردّ فعل: صوت (ToneGenerator عبر قناة أندرويد أصلية — بدون حزم إضافية) + اهتزاز خفيف.
- ماسح USB/بلوتوث (HID): يُعامل كلوحة مفاتيح؛ حقل نصي مخفي يلتقط الإدخال المنتهي بـ Enter.
- تشغيل بيد واحدة: السلة والإجمالي والإتمام في النصف السفلي.

## 4. النموذج المحاسبي (تحقّق)

| المبدأ | التطبيق |
|---|---|
| Append-only ledgers | كل قيد عميل/مورد/مخزون يحفظ `before/after` ولا يُعدّل أبدًا؛ الإلغاء ناعم بسبب |
| الأرصدة مشتقّة | `balance = Σ active ledger rows` — لا رصيد مخزّن |
| وحدة عمل ذرّية | `LedgerDb.run()`: فاتورة + مخزون + دين تُكتب معًا أو لا تُكتب |
| ترتيب الكتابة | الدفاتر أولًا ثم رؤوس المستندات (سلامة عند الانقطاع) |
| نقود صحيحة | `Money` = int بالقروش؛ لا float إطلاقًا |
| COGS لحظي | تكلفة الصنف تُلتقط لحظة البيع (`unitCost`) — تغيّر سعر الشراء لاحقًا لا يغيّر ربح الفواتير القديمة |
| المصاريف التشغيلية | دفعات الموردين مستثناة (سداد التزام لا مصروف)؛ الشراء النقدي مصروف بضاعة |
| الخصم | ≤ الإجمالي؛ الصافي ≥ 0 |
| الرقابة | حد ائتمان + تجاوز موثّق، تجميد، معاملات كبيرة، سجل تدقيق كامل |

### ثوابت (Invariants) تُختبر آليًا
1. Σ(customerTx active) == customerBalance لكل عميل.
2. Σ(stockMoves active) == stockOf لكل صنف.
3. إلغاء الفاتورة يعيد الرصيد والمخزون **بالضبط** إلى ما قبلها.
4. لا فاتورة نشطة بصافي سالب.
5. export → wipe → import يعطي نفس الأرصدة.
6. تكرار الباركود مرفوض.

## 5. الواجهة والهوية

- Material 3، RTL كامل، ثيم **فاتح/داكن/نظام** محفوظ.
- لون الهوية: زمردي `#10B981` (فاتح) / `#34D399` (داكن) — تباين ≥ 4.5:1 للنصوص.
- أيقونات Material Symbols موحّدة (outlined في الحالة العادية، filled للمحدد).
- لا شاشة بدون: عنوان، حالة فارغة مصمّمة، حالة تحميل، رسالة خطأ بشرية.
- الأزرار الرئيسية ≥ 50dp ارتفاع؛ الأرقام بخط عريض tabular.

## 6. الهوية على المطبوعات (البيان العلوي/السفلي)

مصادر: ممارسات نقاط البيع الصغيرة (Loyverse، Square، Vend) — كل مطبوعة تحمل: شعار، اسم المحل، بيان علوي (ترحيب/عنوان/هاتف)، جدول، بيان سفلي (سياسة الإرجاع/شكر).

- تُضبط مرة واحدة من **المزيد ← هوية المحل والطباعة**: الشعار (من الكاميرا أو المعرض، يُصغَّر إلى 512px ويُخزَّن Base64 محليًا ≤ 400KB)، اسم المحل، المالك، الهاتف، العنوان، البيان العلوي، البيان السفلي.
- تُطبَّق تلقائيًا على: فاتورة A4، إيصال 80mm، كشوف حساب العملاء/الموردين، التقارير الدورية/الشهرية، تقرير المخزون، ملصقات الباركود.
- ترويسة موحّدة `PdfBrand`: شعار + اسم + بيان علوي يمينًا، عنوان المستند + الفترة يسارًا؛ تذييل: بيان سفلي + تاريخ الطباعة + رقم الصفحة.
- خط عربي مضمّن **Noto Naskh Arabic** (307KB) — يُشكّل الحروف داخل PDF بلا اعتماد على النظام.

## 7. التقارير والتصدير (PDF / Excel / مشاركة / طباعة)

| المستند | PDF | Excel | ملاحظات |
|---|---|---|---|
| فاتورة بيع A4 | ✓ | — | بنود، خصم، طريقة الدفع، رصيد العميل بعد الفاتورة |
| إيصال 80mm | ✓ | — | لطابعات الحرارية عبر حوار الطباعة الأندرويد (Code128 لرقم الفاتورة) |
| كشف حساب عميل/مورد | ✓ | ✓ (ملف العملاء) | رصيد قبل/بعد لكل حركة، مصدر الحركة |
| تقرير الفترة (يوم/أسبوع/شهر/مخصص) | ✓ | ✓ | KPIs، التدفق النقدي، مبيعات يومية (رسم)، أعلى الأصناف، المصروفات حسب الفئة، المدينون، سجلات المبيعات/المشتريات/المصروفات |
| تقرير شهري | ✓ | ✓ | اختيار أي شهر من آخر 24 شهرًا |
| تقرير المخزون | ✓ | ✓ | A4 أفقي؛ الكمية، التكلفة، قيمة المخزون، تنبيه النقص |
| ملصقات باركود | ✓ | — | 3 أحجام (4/3/2 أعمدة)، نسخ متعددة، EAN-13/EAN-8/UPC-A أو Code128 |

- **المشاركة**: `share_plus` (واتساب/إيميل/درايف…)، **الطباعة**: `printing` (حوار الطباعة الأصلي)، **الحفظ**: مجلد مستندات التطبيق.
- الأصناف بلا باركود تُولَّد لها أكواد Code128 داخلية `GL` + 10 أحرف من المعرّف — قابلة للمسح من الكاشير لأن `productByBarcode` يبحث فيها أيضًا.
- Excel عبر حزمة `excel` (xlsx خام، RTL، صف عناوين مُنسّق) — الأرقام أرقام حقيقية لا نصوص.

## 8. الإدخال الصوتي (قرار)

اختُبر خياران: حزمة `speech_to_text` (تضيف ~1.5MB وتحتاج خدمات Google على الجهاز) مقابل الاعتماد على **ميكروفون لوحة المفاتيح** (Gboard/سامسونج) المتاح في كل حقول النص. القرار: لا حزمة إضافية — كل حقل بحث/اسم/ملاحظة يقبل الإملاء من الكيبورد، مع الإبقاء على APK صغيرًا. يمكن إضافة الحزمة لاحقًا خلف `NativeBridge`.

## 9. خارج النطاق (بقرار)

مزامنة سحابية، عدة فروع، مستخدمون متعددون، ميزان إلكتروني، ضرائب — لأن التعريف «بقالة، جهاز واحد، بلا إنترنت». يمكن إضافتها لاحقًا فوق المحرك دون تغييره.
