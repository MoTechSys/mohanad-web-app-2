# 01 - تحليل المتطلبات

## أ. المتطلبات الوظيفية الأساسية (v1)

### 1. المصادقة والمستخدمون

- تسجيل الدخول (username + password).
- Refresh tokens.
- إعادة تعيين كلمة المرور (بصلاحية).
- تعطيل / تفعيل المستخدم.
- عرض نشاط المستخدم.

### 2. الأدوار والصلاحيات (RBAC ديناميكي)

- إنشاء دور جديد.
- تعديل اسم الدور ووصفه.
- اختيار صلاحيات الدور.
- نسخ دور.
- تعطيل دور.
- تعيين دور لمستخدم.
- قيود إضافية لكل صلاحية عبر `constraints_json`.

### 3. العملاء

- CRUD كامل (مع soft delete).
- سقف دين (`credit_limit`) ورصيد حالي (`current_balance`).
- حالات: نشط / مجمد / مهلة.
- تجميد / فك تجميد / منح مهلة / رفع سقف.
- كشف حساب وطباعته.
- إعدادات تذكير.

### 4. حركات ديون العملاء

- إضافة دين (مبلغ + تفاصيل نصية + تاريخ).
- تسجيل سداد.
- تسوية / تصفير حساب.
- إلغاء حركة (بسبب).
- اعتماد تجاوز السقف.
- اعتماد مبالغ كبيرة.
- طباعة إيصال.

### 5. البيع (3 أوضاع + هجين)

- **بيع تفصيلي**: عميل + أصناف + كميات + سعر + نقد/دين + ملاحظات.
- **بيع سريع بمبلغ**: عميل + مبلغ + تفاصيل نصية + نقد/دين.
- **دخل يومي إجمالي**: مبلغ + ملاحظات.
- إلغاء بيع، استرجاع، خصم، طباعة إيصال، إغلاق يوم، عرض الربح.

### 6. التجار / الموردين

- CRUD مع soft delete.
- رصيد دين على البقالة.
- رصيد افتتاحي.
- كشف حساب.

### 7. حركات التجار

- مشتريات آجلة (ترفع الدين).
- مشتريات نقدية (لا ترفع الدين).
- دفع لتاجر (يقلل الدين).
- تسويات / إلغاء.

### 8. المشتريات

- شراء إجمالي فقط (بدون أصناف).
- شراء تفصيلي (بأصناف وكميات).
- نقد أو آجل.
- إلغاء، اعتماد، طباعة فاتورة.

### 9. المصاريف والخرج

- خرج عادي (غداء، كهرباء، إيجار، رواتب...).
- دفع لتاجر (لا يحسب كمصروف تشغيلي).
- شراء نقدي.
- تصنيفات المصاريف.
- إلغاء واعتماد.

### 10. الدخل اليومي

- إدخال دخل اليوم الإجمالي.
- هدف يومي.
- COGS يدوي اختياري.
- اعتماد، طباعة.

### 11. المنتجات والمخزون (اختياري)

- CRUD منتج (اسم، باركود، وحدة، سعر شراء، سعر بيع، حد أدنى).
- تتبع مخزون على مستوى المنتج (`track_inventory`).
- تفعيل/تعطيل المخزون كاملاً (`inventory_enabled`).
- حركات مخزون: دخول / خروج / تعديل / إلغاء.

### 12. التقارير

- يومي / أسبوعي / شهري.
- ربح وخسارة (دقيق / تقديري / يدوي).
- تدفق نقدي.
- ديون العملاء وكشف حساب.
- ديون التجار وكشف حساب.
- مشتريات / مصاريف / مخزون.
- نشاط العمال.
- سجل الحركات.
- تحليل سلوك العملاء.
- 3 صلاحيات لكل تقرير: عرض / طباعة / تصدير.

### 13. الإشعارات

- إشعارات داخلية (in-app).
- زر واتساب برسالة جاهزة (بدون API تلقائي).
- قوالب رسائل.
- جدولة تذكيرات للعملاء.

### 14. سجل الحركات (Audit Log)

- لكل: إنشاء / تعديل / إلغاء / حذف ناعم / تغيير صلاحية / تسجيل دخول / محاولة وصول مرفوضة.
- old_values / new_values.
- IP و User Agent.

### 15. الإعدادات

- اسم البقالة، العملة، طريقة البيع الافتراضية.
- تفعيل/إيقاف: المخزون، تحليل العملاء، الإشعارات.
- أهداف يومية، قالب واتساب.

## ب. المتطلبات غير الوظيفية

| المتطلب | الوصف |
|---|---|
| الأمان | JWT + Refresh tokens، تحقق صلاحيات في كل API. |
| الموثوقية | كل عملية مالية داخل Prisma transaction. |
| الأداء | فهرسة قاعدة البيانات على store_id, customer_id, supplier_id, dates. |
| التوافر | PWA يفتح من الكاش، لكن العمليات تحتاج اتصال. |
| اللغة | عربي بالكامل، RTL. |
| الجوال أولاً | Mobile-first بـ Ionic. |
| التوسع | store_id موجود لدعم متعدد المتاجر مستقبلاً. |
| Audit | لا حذف نهائي، كل شيء يسجل. |

## ج. المتطلبات اللاحقة (مؤجلة بعد v1)

1. دعم متعدد المتاجر فعلياً (UI + tenant isolation).
2. واتساب API تلقائي.
3. عمل أوفلاين (Offline-first) للعمليات المالية.
4. تطبيق موبايل أصلي (React Native).
5. تطبيق سطح مكتب.
6. باركود سكانر متقدم.
7. تكامل مع طابعات حرارية.
8. نسخ احتياطية تلقائية (ميزات متقدمة فوق Railway).
9. تكامل دفع إلكتروني.
10. تقارير ذكاء اصطناعي / تنبؤات.
11. تطبيق للعميل لرؤية رصيده.
12. صور للمنتجات والميديا.

## د. القيود المهمة (Constraints)

> هذه القيود **ملزمة** ولا يجوز كسرها في أي مرحلة من التنفيذ.

1. **لا حذف نهائي للعمليات المالية**: استخدم `cancelled_at` أو `deleted_at` فقط.
2. **كل العمليات المالية تمر عبر الباكند**: الفرونت لا يحدث الأرصدة مباشرة.
3. **كل تعديل أو إلغاء يسجل في audit_logs**: مع old_values و new_values.
4. **الواجهة تخفي/تظهر المزايا حسب الصلاحيات**: لكنها ليست الحماية الحقيقية.
5. **الباكند يتحقق من الصلاحيات في كل API**: عبر Guards على كل endpoint.
6. **العمليات المالية داخل Prisma transactions**: بدون استثناء.
7. **قاعدة البيانات Railway PostgreSQL فقط**: ممنوع Supabase / Neon / غيرها.
8. **لا تخزين صور أو ميديا في v1**.
9. **لا واتساب API تلقائي في v1**: زر فقط برسالة جاهزة.
10. **لا أوفلاين للعمليات المالية في v1**.
